# Michael's Foundation Projects
## Coding Standards

---

# Purpose

This document establishes the coding standards that will be followed throughout every Foundation Project.

These standards exist to make every project:

- Easy to read
- Easy to maintain
- Easy to expand
- Consistent across all applications

> Good software is organized software.

---

# Folder Organization

Each Foundation Project should follow a consistent folder structure whenever possible.

Example:

Project Name
- css
- images
- js
- documentation
- index.html

---

# File Naming

Use meaningful names.

Examples:

- index.html
- style.css
- main.js
- Developer Journal.md

Avoid vague names such as:

- file1
- test
- new
- temp

---

# HTML Standards

- Use semantic HTML whenever possible.
- Indent code consistently.
- Group related elements together.
- Use comments to identify major sections.

Example:

```html
<!-- Navigation -->
```

---

# CSS Standards

- Organize styles into logical sections.
- Begin each section with a descriptive comment.
- Group related properties together.
- Prefer readability over brevity.
- Keep spacing consistent.

---

# Comments

Every file should begin with:

- Purpose
- Author
- Last Updated

Comments should explain:

- Why something exists
- Design decisions
- Purpose

Avoid comments that simply repeat the code.

---

# Naming

Choose names that describe purpose.

Good:

- hero-button
- project-card
- mission

Avoid:

- box1
- thing
- test

---

# Design Philosophy

Every Foundation Project should share a consistent visual identity.

Current standards:

- Blue headings
- White content cards
- Rounded corners
- Soft shadows
- Blue outlined buttons
- Professional spacing

---

# Developer Principles

1. Code is read more often than it is written.

2. Organization is part of programming.

3. Consistency is more important than decoration.

4. Comments explain **why**, not **what**.

5. Make future maintenance easy.

6. Build software that another developer can understand.

# Teaching Through Code

This project is intended to educate as well as function.

Whenever practical:

- Choose clarity over cleverness.
- Write code that teaches.
- Document important design decisions.
- Organize files so another developer can learn from them.
